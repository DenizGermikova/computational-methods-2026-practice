## 1. Мета роботи, номер варіанта, предметна область

Розробити програму-агента, яка самостійно визначає, які інструменти необхідно використати для виконання запиту користувача, передає їм потрібні аргументи, отримує результати та формує на їх основі кінцеву відповідь.

**Варіант № 2. Предметна область — кулінарія.**

Агент призначений для пошуку рецептів за інгредієнтами, типом страви або способом приготування, отримання інформації про калорійність і вартість продуктів, а також перерахунку кількості інгредієнтів відповідно до заданої кількості порцій.

Під час виконання роботи перевіряється здатність агента правильно вибирати інструменти, послідовно виконувати необхідні дії, використовувати отримані результати та не вигадувати інформацію, якої немає в доступних даних.

**Параметри агента за `config.py`:** модель `qwen3:4b`, сервер Ollama `http://localhost:11434/v1`, `MAX_STEPS = 6`, `TEMPERATURE = 0`.

## 2. Вихідні дані та параметри агента

Для роботи агента використовується корпус текстових файлів із рецептами та довідник продуктів.

- **Корпус рецептів** міститься в `data/recipes/`: **12 файлів `.txt`** (`recipe_01.txt` — `recipe_12.txt`). У них наведені назви страв, типи, кількість порцій, інгредієнти та спосіб приготування.
- **Довідник продуктів** `data/products.csv`: **20 записів**, не рахуючи заголовок. Стовпці: `product`, `kcal_per_100g`, `price_per_kg`.
- **Контрольні питання** `tasks.json`: **5 завдань** — Z1, Z2, Z3 (основні) та P1, P2 (задачі-пастки).

У наборі є страви різних типів (основні страви, супи, салати, десерти) і способів приготування (у духовці, на сковороді та без термічної обробки). Назви й значення перевірені за файлами поданої лабораторної.

## 3. Опис інструментів агента

Для виконання запитів користувача агенту доступні три інструменти: `search_recipes`, `product_info` та `scale_amount`. Їх описи для мовної моделі містяться в `schemas.py`.

### Інструмент `search_recipes`

Призначений для пошуку рецептів у корпусі за текстовим запитом користувача. Аргумент `query` — рядок із назвою страви, інгредієнтом або іншим пошуковим запитом. Інструмент шукає точний підрядок у текстових файлах і повертає назви знайдених рецептів, розділені символом `|`. Якщо результатів немає, повертається повідомлення про відсутність збігів.

### Інструмент `product_info`

Призначений для отримання інформації про калорійність і вартість продукту з довідника `data/products.csv`. Аргумент `product` — назва продукту. Інструмент повертає калорійність на 100 грамів і ціну за кілограм або повідомлення про відсутність продукту. Наприклад, для «рис» у контрольному журналі отримано **360 ккал на 100 г** і **55 грн/кг**.

### Інструмент `scale_amount`

Призначений для перерахунку кількості інгредієнта відповідно до зміни кількості порцій. Аргументи: `amount`, `base_servings`, `target_servings` — початкова кількість інгредієнта, кількість початкових порцій і бажана кількість порцій.

Формула: `amount × target_servings / base_servings`. Для 300 г рису на 4 порції при переході до 10 порцій інструмент повернув **750 г**.

| Інструмент | Аргументи | Призначення |

## 7. Розбір одного провалу — Z1

**Завдання Z1:** «Знайди щось із куркою».

**Очікувана поведінка:** агент мав знайти рецепт із куркою та надати відповідний результат.

**Фактична поведінка:** викликано `search_recipes` з `{"query":"курка"}`. Пошук не знайшов відповідних рецептів, після чого агент повідомив про відсутність результату.

**Фрагмент коду `tools.py`, що пояснює причину невдалого пошуку:**

```python
def search_recipes(query: str) -> str:
    query = query.strip().lower()
    if not query:
        return "Порожній пошуковий запит."
    found = []
    for path in sorted(RECIPES_DIR.glob("*.txt")):
        content = path.read_text(encoding="utf-8")
        if query in content.lower():
            first_line = content.splitlines()[0].strip()
            found.append(first_line)
    if not found:
        return f"За запитом '{query}' нічого не знайдено."
    return " | ".join(found)
```

**Повний фрагмент `lab2.log` для завдання Z1 без скорочень:**

```text
2026-10-27 20:37:43,358 | INFO | 
=== Z1 | Очікується: Назва рецепта з куркою
2026-10-27 20:37:43,359 | INFO | 
============================================================
2026-10-27 20:37:43,359 | INFO | ЗАДАЧА: Знайди щось із куркою
2026-10-27 20:38:09,386 | INFO | 
--- крок 1 | prompt_tokens=754
2026-10-27 20:38:09,390 | INFO | ВИКЛИК: search_recipes({"query":"курка"})
2026-10-27 20:38:09,397 | INFO | РЕЗУЛЬТАТ: За запитом 'курка' нічого не знайдено.
2026-10-27 20:39:31,240 | INFO | 
--- крок 2 | prompt_tokens=1161
2026-10-27 20:39:31,242 | INFO | ВІДПОВІДЬ: Запит "курка" не знайдено.
```

**Аналіз причини.** У наведеному коді умова `if query in content.lower()` шукає точний підрядок. Вона не враховує українських словоформ. Тому «курка» не збігається з «куркою» або «курячий», якщо точна послідовність символів `курка` відсутня в тексті. Після невдалого першого пошуку агент не переформулював запит.

**Можливе усунення:** удосконалити алгоритм пошуку, додавши пошук за словоформами, лематизацію або кілька альтернативних запитів. Для роботи агента також варто передбачити повторну спробу з іншими ключовими словами після порожнього результату.

**Висновок:** причина невдачі — обмеження простого текстового пошуку та відсутність уточнення запиту, а не некоректний JSON чи помилка Python.

## 8. Відповіді на контрольні запитання

**1. Скільки завдань виконано правильно?**  
Правильно виконано **3 із 5**: Z2, Z3 і P1. У двох інших випадках очікуваного результату не досягнуто.

**2. Яка поламка траплялася найчастіше?**  
Одна повторювана поламка не виділяється: у стандартній класифікації зафіксовано один неправильний вибір інструмента (P2), а окремо — невдалу стратегію пошуку (Z1).

**3. Чи був випадок, коли агент вигадав результат, не викликавши інструмент?**  
Ні. У кожній із п'яти задач агент викликав хоча б один інструмент і не повідомив вигаданий рецепт як знайдений.

**4. Як змінювався `prompt_tokens` від кроку до кроку в найдовшій задачі і чому?**  
Найбільше зростання кількості токенів зафіксовано в **P1**: із **770** на першому кроці до **2755** на другому (+1985). Причина — до нової ітерації включено історію звернень та результат інструмента. У Z2 для порівняння було зростання від **767** до **1980**.

**5. Чи пройшов агент перевірку на пастки?**  
Завдання **P1 пройдено** — агент чесно повідомив, що рецепт відсутній. Завдання **P2 не пройдено** — замість прямого пояснення відсутності інструмента для списку покупок агент здійснив нерелевантний пошук.

## 9. Висновки

Під час виконання лабораторної роботи було розроблено та протестовано кулінарного агента, який використовує мовну модель та зовнішні інструменти для пошуку рецептів, отримання інформації про харчову цінність продуктів і перерахунку кількості інгредієнтів.

У ході тестування перевірено п'ять завдань. Агент успішно знайшов страви з рисом, визначив його калорійність і правильно перерахував кількість рису для десяти порцій. У завданнях Z1 і P2 виявлено обмеження пошукового інструмента та труднощі з визначенням доступних дій.

**Найскладнішою проблемою** виявилася недостатня гнучкість пошуку рецептів, оскільки алгоритм перевіряє точний підрядок і не враховує словоформи. Для покращення роботи агента можна реалізувати пошук із підтримкою словоформ та чіткіше описати обмеження інструментів.

**Найнебезпечнішою для реальної системи** є здатність агента вибрати невідповідну дію або заявити про виконання недоступної операції. У проведеному досліді він не стверджував, що справді змінив список покупок, але не дав достатньо чіткої відмови. Реальна система повинна перевіряти допустимість інструментів і чесно повідомляти користувача про свої обмеження.

Отже, у лабораторній роботі перевірено взаємодію мовної моделі з інструментами, передавання аргументів, обробку результатів і поведінку агента в ситуаціях, коли інформація або функціональність недоступні.
